# 隐私与仓库边界

## 最高原则

这个文件夹保存可公开复用的方法论，不保存任何人的个人信息。private 只是当前访问设置，不是存储个人信息的理由。

“个人信息”不仅包括身份标识，还包括能描述真实个体的生活安排、行为习惯、偏好、健康情况和关系信息。即使没有姓名，也不得把真实记录作为本仓库内容。

## 存储边界

| 内容 | 本仓库 | 仓库之外的独立私有空间 |
| --- | --- | --- |
| 通用流程与空白模板 | 可以 | 可以复制使用 |
| 通用提示词 | 可以 | 可以填入个人上下文 |
| 从零构造、明确标记的虚构示例 | 可以 | 可选 |
| 填写后的计划、偏好与复盘 | 不可以 | 由使用者管理 |
| 日历、健康记录、位置与联系人 | 不可以 | 按必要性与授权管理 |
| 密钥、令牌、密码、账号导出 | 不可以 | 由专门的凭据机制管理 |

不在此文件夹新建“个人数据区”，也不将 Git 忽略目录当作私有保险箱。`.gitignore` 只是防止误提交的额外防线。

## 使用 AI 时的数据最小化

1. 先确认任务是否真的需要某项信息。
2. 能用可用时段、路线代号、预算范围等抽象约束完成时，不提供姓名、地址或完整日历。
3. 精确位置、医疗记录、联系人等仅在确有必要、获得授权且了解工具数据处理方式后，在独立私有环境中使用。
4. 提示词只索取当前任务所需字段，允许“不提供”与“待确认”。
5. 私有工具的输出不自动回流本仓库。贡献方法改进时，重新编写为通用规则。

## 长期观察与见面记录

历史书单、饮食估算、穿戴数据、跨领域总结和活动评估均属于个人内容，仅在仓库之外处理。本仓库只定义所需字段、用途和数据质量规则，不以“全面了解”为由持续收集全部生活资料。

录音与转写默认关闭。确有必要时，按[活动记录约定](activity-evaluation.md)先取得全体明确同意、核实适用规则，并对转写、外部 AI 上传及分享分别确认；保存、访问与删除也在私有空间管理。纪要和自述同样不能回写仓库。

## 自动检查的边界

`scripts/check_repository.py` 检查参与发布的文件、链接、常见邮箱、电话形式、设备绝对路径和密钥模式，并拒绝未约定的发布路径与二进制内容。它不能识别所有姓名、真实经历、隐含身份线索或混淆后的凭据。

文件是否构成个人信息，最终需要人工逐项审查。检查通过不等于已经完整匿名化。

## 意外写入后的处理

- 尚未提交：停止暂存与推送，识别涉及范围，在仓库外完成必要处置；不要在报告或提交说明中复述敏感值。
- 已经提交：停止进一步传播，检查本地和远端历史；仅删除当前文件不能移除历史版本。
- 涉及有效凭据：优先撤销或轮换，并检查已经传播的范围。
- 历史重写、远端清理及其他影响协作者的操作，应明确范围并获得相应授权。
- 仅记录不含个人信息的治理改进，不保存原始泄露样本。

## 仓库元数据

提交作者、提交正文、签名、远端访问凭据和自动化日志也属于审查范围。贡献者应使用不含个人身份的项目通用提交身份，避免把工作站路径与本机环境输出提交到仓库。托管平台的仓库所有权及访问审计记录由平台管理，不应复制进方法论正文。
