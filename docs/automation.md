# 自动化分级与授权

自动化用于减少重复劳动。是否启用、范围多大、何时停止，应在执行前说明。

## 分级

| 级别 | AI 可以做什么 | 启用条件 |
| --- | --- | --- |
| A：建议 | 整理输入、比较方案、生成清单 | 当前任务上下文足够 |
| B：草拟 | 草拟日程、邀约、采购单 | 明确标记“未创建／未发送／未购买” |
| C：私有写入与提醒 | 在私有工具中写计划或创建提醒 | 使用者确认工具、字段、频率、有效期和撤销方法 |
| D：对外执行 | 发消息、预约、购买、付款或共享位置 | 对具体动作与影响有明确授权，金额、对象等关键范围已确认 |

等级是本仓库的治理约定，不代表已经开发了对应的集成。一次授权不会自动扩展到其他工具、联系人、时段或操作。

## 启用前的约定

使用[自动化约定模板](../templates/automation-contract.md)记录：

- 任务目的与允许的动作。
- 所需输入、访问范围和存储位置。
- 触发条件、重复频率、有效期和静默条件。
- 关键结果如何核验。
- 失败、重试和重复执行如何处理。
- 何时必须再次询问。
- 如何暂停、撤销权限与清理数据。

这些填写内容只存在于仓库之外。

穿戴数据读取需明确字段、观察范围、用途与访问有效期，不默认全量读取健康历史。录音、转写、上传外部 AI 与分享分别确认；一次见面的允许录音不延伸到未来见面。相关方法见[活动评估](activity-evaluation.md)。本文件只规定授权，未创建任何设备连接或录音任务。

## 提醒规则

提醒前先确认“什么时候提醒”和“什么情况不用提醒”。默认不把所有未完成事项升级成更多通知。允许跳过、延后、暂停，并避免在未经确认的休息时段打扰。

## 执行证据

区分草稿生成、请求提交、工具受理和实际完成。只有可靠回执或使用者反馈才能确认相应阶段；发出邀请不等于对方接受。

请求超时后先核对状态，再决定是否重试。无法确认是否成功的购买、预约或发送动作，不能盲目重复。

## 停止条件

权限过期、输入不完整、事实冲突、数据超出授权范围或动作结果不确定时，停止受影响动作并说明原因。替代方案仍需满足原授权边界。

自动化不得向本仓库回写个人计划、工具日志或执行回执。
