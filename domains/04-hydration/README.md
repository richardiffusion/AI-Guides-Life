# 喝水

围绕取水、携带、场景切换和提醒，减少日常喝水流程中的阻力。

本指南不设适用于所有人的每日饮水量，不根据少量描述判断缺水或其他健康问题。

## 私有输入

在仓库外按需提供：取水便利性、携带条件、通勤或活动环境、提醒接受程度，以及已经明确的饮水限制。无需提供完整身体或医疗资料。

## 操作流程

1. 先确认问题是忘记、取水不方便、携带困难还是提醒过多。
2. 若已有专业明确的限制，将其作为硬约束，不由 AI 调整。
3. 选择一个能自然衔接的场景触发，例如离开固定场所前检查水杯。
4. 优先改善环境，再决定是否需要通知。
5. 如需提醒，确认频率、静默条件、暂停方式与结束时间。
6. 记录是否有帮助及是否造成干扰，按反馈减少或调整提醒。

## 可复制提示词

> 请只围绕取水、准备、携带和提醒设计一个喝水流程。依据我提供的场景与明确限制，给出一个主动作和一个最低版本。不要预设固定饮水量，不要求为了完成目标强行喝水。需要提醒时，先列出待确认的频率、静默时段与停止条件，不自行创建提醒。

## 预期输出

触发场景、准备动作、提醒条件、跳过规则和复查条件。提醒接入前填写[自动化约定](../../templates/automation-contract.md)。

## 回退与复盘

没有取水条件时，优先改善准备与路径，不靠事后集中补量“补做”。有明确饮水限制或出现不适时，尊重限制并让适当的专业判断参与。

复盘关注环境是否更便利、通知是否有用、记录是否太复杂；避免把单一打卡数字当作健康效果。
