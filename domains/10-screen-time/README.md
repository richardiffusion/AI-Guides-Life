# 手机屏幕使用时间

在仓库外持续了解手机使用的总量、用途、时段和打断情况，结合实际需要与其他生活领域形成阶段建议，再落实到月、周、日安排。目标由使用者选择，可以是减少不想要的使用、保留有价值的活动或改善某个时段，不以时长越少越好为统一标准。

## 私有输入

只提供当前问题需要的系统汇总或手动记录：观察目标、日期范围、日类型、设备范围、来源、覆盖情况和每日总时长。应用分类、重点时段与主观反馈按需增加；无需完整应用清单、访问内容、网站历史、联系人或账号。

真实记录、系统截图、导出、应用使用习惯及其分析均属于个人内容，只在仓库之外的独立私有空间处理。优先手动整理必要汇总，应用可使用通用类别或代号；不默认读取设备、上传截图或安装监控软件。

## 记录字段

以下“最低记录”用于建立可比较的汇总，不是强制收集要求；缺少字段时保留未知并缩小结论范围。

| 层级 | 字段与口径 | 用途与记录频率 |
| --- | --- | --- |
| 最低记录 | 当前问题、希望保留的用途、观察起止与复查条件 | 周期开始确认，目标变化时更新 |
| 最低记录 | 日期、时区、日界线与工作日／休息日／出行等日类型 | 每日汇总时记录，便于比较相近情境 |
| 最低记录 | 系统或手动来源、软件版本、通用设备代号、单台手机或跨设备范围 | 初次及来源变化时更新；不记录账号与设备序列号 |
| 最低记录 | 每日屏幕使用总时长，统一为分钟，并保留原始显示单位 | 日末或约定时间汇总；当天未结束需注明截止时点 |
| 最低记录 | 完整／部分／未知、缺失原因、是否启用跨设备共享、统计口径变化 | 每次汇总核对；未提供的数据不填零 |
| 可选扩展 | 主要应用或类别的分钟数、类别映射、未分类部分 | 按当前问题选择少量项目，不要求完整列表 |
| 可选扩展 | 工作、学习、阅读、沟通、导航、娱乐等用途及混合／未知部分 | 由使用者自述；系统应用类别不能直接代替实际用途 |
| 可选扩展 | 拿起、解锁、应用打开次数，各自保留系统原标签及单位“次” | 平台提供且与问题相关时记录，不能视为同一指标 |
| 可选扩展 | 通知总数或选定类别的通知数，单位“条”及统计范围 | 分析打断线索；通知数不等于实际被打断次数 |
| 可选扩展 | 睡前、起床后、工作、阅读或通勤等自定义观察窗口及其中的使用分钟数 | 明确窗口起止、跨日归属和取得方式，不编造小时级明细 |
| 可选扩展 | 单次使用时长、切换或连续使用情况及其来源 | 仅有可靠明细或自愿手记时使用，不从日总量反推 |
| 可选扩展 | 使用是否符合原意、主观专注与休息感受、受影响的事项、必要例外 | 简短自述即可，不能由 AI 从应用名称推断 |
| 可选扩展 | 尝试的调整、计划与实际、提醒或限制是否执行、负担和替代行为 | 调整后反馈；没有操作回执或自述不能认定已设置 |

可用[手机屏幕使用时间记录与复盘模板](../../templates/screen-time-review.md)在仓库外组织这些字段。每项指标单独说明实际覆盖，不要求为了“全面了解”而持续逐次记录。

## 数据口径与汇总

- 先确认“只看这台手机”还是“跨设备报告”。跨设备总计与单台数据不能重复相加；不同设备同时使用时，设备分钟之和也不能直接当作人的不重复占用时长。
- 总量、应用和类别可能属于不同层级或统计范围。浏览器与站点明细、总计与子项不重复累计；不能核对时保留差异，不强行凑齐。不同平台的拿起、解锁与打开次数分别比较。
- 漏记、功能未启用、记录尚未同步、当天未结束与确实零使用分开。系统报告值、手动估计、用途自述和 AI 推断分开；来源或统计范围改变后标记比较边界。
- 周期汇总列出纳入日期、各指标有效天数与覆盖缺口。可比完整日的日均时长为这些日总量之和除以这些日的有效天数；部分日另列，不当完整日纳入，也不将缺失日补零。
- 比较相近日类型与相同口径。变化量先报告分钟差；报告比例变化时说明基线和分母，基线为零或未知时不计算变化率。用途占比仅在分类互斥、分子与分母范围一致时计算，并保留混合或未知部分。
- 日均时长不等于“典型一天”，总时长也不等于注意力、效率或健康状况。睡前使用与睡眠变化同时出现只能作为讨论线索，不能直接证明因果或诊断“成瘾”。

## 操作流程

1. 选定一个问题、需要保留的手机用途及观察情境，约定起止、最低字段与复查条件。不预设统一的每日时长上限或固定观察天数。
2. 核对系统现有汇总的设备范围、时间口径和可用字段。优先整理已有数据；没有可靠汇总时先用低负担手记，并明确它是估计。
3. 先看覆盖再看趋势，按工作日、休息日或出行情境比较总量、用途结构和重点窗口。没有明细时只讨论总量，不能补造应用排名、通知数或使用动机。
4. 由使用者判断哪些使用值得保留、哪些超出原意。学习与工作之外的娱乐、沟通和休息也可以有价值；不根据时长给人格、自律或人际关系打分。
5. 形成带依据的少量候选调整，例如调整某类非必要通知、约定主动查看窗口、修改某个时段的手机放置方式或准备替代活动。一次先尝试一个变量，保留必要沟通、工作、导航和无障碍需求；实际设置按[自动化约定](../../docs/automation.md)另行授权。
6. 接入日常作息：月尺度确定方向与边界，周尺度选择观察情境和一次尝试，日尺度记录最低反馈；不要把所有手机时间都作为可回收时间加入计划。
7. 比较调整前后相近情境，查看实际改善、任务完成、休息体验和执行负担；检查是否转移到其他设备或用途，决定保留、修订或撤销，而不是只追求总时长下降。

## 可复制提示词

> 请根据我在独立私有空间提供的手机屏幕使用汇总、目标与必要约束，先核对日期、时区、日类型、设备范围、来源及各指标覆盖，区分完整日、部分日、漏记和零值。分别整理总时长、应用或用途结构、拿起／解锁／打开次数、通知及我选定的时段；未提供的指标保留待确认。说明日均与变化的有效天数和分母，不将跨设备、类别子项或重叠活动重复累计，不从应用类别推断动机或价值。由我确认值得保留与希望调整的使用，给出现状、限制、一个可选调整及缩减方案，连接月周日安排并约定复查和撤销条件。不设统一时长标准，不作健康诊断或因果判断，不读取设备、不修改通知或限额，不保存或回传真实记录。

## 预期输出

数据范围与质量说明、可比较的现状和变化、用途与重点时段的已知情况、尚不能判断的部分、由使用者确认的取舍、一次调整及月周日安排、复查与停止条件。每项建议包含依据、必要例外、不确定性与执行负担。

## 回退与复盘

只有总量时不补造明细；没有完整日时先描述已有范围，不强算日均。记录负担高时只保留目标、口径、总量、覆盖和一句反馈，或降低汇总频率。限制影响必要任务、沟通或使用便利时先撤销或缩小范围；撤销需有实际确认，不把草稿当作已完成。

复盘关注使用是否更符合意图、重要事项和休息是否获得空间，而非单一数字。时长下降但负担增加、转移到其他设备或失去有价值活动时，重新确认目标。跨领域配合见[作息指南](../01-daily-routine/README.md)、[跨领域协调](../../docs/cross-domain.md)与[持续观察方法](../../docs/longitudinal.md)。

## 来源与适用范围

以下官方功能说明核实于 2026-11-09，仅用于选择可用字段，不作为健康效果或统一时长标准的依据：

- [Apple iPhone 屏幕使用时间指南](https://support.apple.com/en-ie/guide/iphone/iphbfa595995/27/ios/27)：该版本说明支持日／周摘要、拿起与通知报告，以及跨设备共享与汇总。使用时核对实际系统版本与设备选择；不将该版本菜单或功能视为适用于全部设备，也不代表本项目已接入。
- [Google Android 数字健康说明](https://support.google.com/android/answer/9346420)：在部分手机上可查看屏幕时间、打开相关次数与通知信息。功能及步骤因设备而异；未显示的字段保留未知，不能假定可自动导出或由 AI 直接读取。

来源页面、系统版本或指标定义变化时重新核实。是否启用统计、读取权限、保留期限和分享范围由使用者在仓库外确认，不索取设备密码或限制密码。
